# დავალება: Git-ით გუნდური თანამშრომლობა

## მიზანი

ამ დავალების მიზანია, ისწავლოთ Git-ისა და GitHub-ის გამოყენებით გუნდური მუშაობა — branch-ების შექმნა, Pull Request-ების გახსნა, კოდის გადახედვა (code review) და merge conflict-ების მოგვარება.

---

## ეტაპი 1: საწყისი მომზადება (ლიდერი)

გუნდის ლიდერმა უნდა:

1. შექმნას ახალი **public repository** GitHub-ზე სახელით `team-git-homework`.
2. დაამატოს `README.md` ფაილი გუნდის წევრების სიით.
3. დაამატოს `.gitignore` ფაილი.
4. დაამატოს ყველა გუნდის წევრი **collaborator-ად** (Settings → Collaborators).
5. დაიცვას `main` branch (Settings → Branches → Branch protection rules):
   - Pull Request-ის გარეშე merge აკრძალულია.
   - საჭიროა მინიმუმ **1 review**-ის დადასტურება.

---

## ეტაპი 2: ლოკალური მუშაობა (ყველა წევრი)

თითოეულმა წევრმა უნდა:

```bash
# Repository-ის ლოკალურად ჩამოტვირთვა
git clone https://github.com/<username>/team-git-homework.git
cd team-git-homework

# საკუთარი branch-ის შექმნა
git checkout -b feature/<შენი-სახელი>
```

---

## ეტაპი 3: ფუნქციონალის დამატება (თითოეული წევრი)

თითოეულმა გუნდის წევრმა უნდა შექმნას **საკუთარი ფაილი** `members/` საქაღალდეში სახელით `<შენი-სახელი>.md` და ჩაწეროს:

- სახელი და გვარი
- საყვარელი პროგრამირების ენა
- მოკლე ბიოგრაფია (2–3 წინადადება)
- რატომ აირჩიეთ პროგრამირება

ასევე, **საერთო ფაილში** `team.md` დაამატეთ თქვენი სახელი სიაში. ⚠️ ეს ფაილი ჩაფიქრებულია ისე რომ გამოიწვიოს **merge conflict**-ი

---

## ეტაპი 4: Commit და Push

```bash
git add .
git commit -m "feat: დაემატა <შენი-სახელის> პროფილი"
git push origin feature/<შენი-სახელი>
```

---

## ეტაპი 5: Pull Request

1. გახსენით **Pull Request** GitHub-ზე.
2. სათაურში მიუთითეთ: `Add <შენი-სახელის> profile`.
3. აღწერაში დაწერეთ რა ცვლილებები შეიტანეთ.
4. მონიშნეთ მინიმუმ **ერთი გუნდის წევრი** reviewer-ად.

---

## ეტაპი 6: Code Review

თითოეულმა სტუდენტმა უნდა გადახედოს მინიმუმ **ორი** გუნდის წევრის Pull Request-ი:

- დატოვეთ კონსტრუქციული კომენტარები.
- მიუთითეთ მინიმუმ ერთი წინადადება გასაუმჯობესებლად.
- დაამტკიცეთ (Approve) მხოლოდ მაშინ, თუ კოდი მზად არის.

---

## ეტაპი 7: Merge Conflict-ის მოგვარება

რადგან ყველა წევრი არედაქტირებს `team.md` ფაილს, წარმოიქმნება conflict-ები.

```bash
# main-ის ბოლო ცვლილებების ჩამოტანა
git checkout main
git pull origin main

# შენს branch-ში დაბრუნება
git checkout feature/<შენი-სახელი>
git merge main

# Conflict-ის ხელით მოგვარება ფაილში
# შემდეგ:
git add team.md
git commit -m "fix: მოგვარდა merge conflict team.md-ში"
git push origin feature/<შენი-სახელი>
```

---

## ეტაპი 8: საბოლოო Merge

გუნდის ლიდერი ან Pull Request-ის ავტორი merge-ავს PR-ს `main` branch-ში მას შემდეგ, რაც:

- ✅ მინიმუმ ერთი review დადასტურებულია
- ✅ Conflict-ები მოგვარებულია
- ✅ ყველა კომენტარი დახურულია

---


1. რეპოზიტორიის ბმული
2. ყველა გუნდის წევრის სია
3. მოკლე აღწერა (1 აბზაცი) — რა გაგიჭირდათ ამ დავალებაში

---

## სასარგებლო ბრძანებები

```bash
git status                    # მიმდინარე მდგომარეობის ნახვა
git log --oneline --graph     # commit-ების ისტორია
git branch -a                 # ყველა branch-ის ნახვა
git diff                      # ცვლილებების ნახვა
git stash                     # ცვლილებების დროებითი შენახვა
```
